# /radar-ship — 기능 출시 매뉴얼

**대표가 `/radar-ship` 이라고 부를 때만 실행한다. 스스로 실행하지 않는다.**

## ① 고르기
- `$ARGUMENTS` 에 기능 번호(F1/F2/F3)가 있으면 그 기능.
- 없으면 PRD.md 「출시 체크」에서 체크 안 된 첫 기능을 고르고, **대표에게 "○○부터 할까요?" 먼저 묻는다.**

## ② 만들기 · 마무리
- CLAUDE.md 규칙을 지킨다. PRD에 없는 기능은 추가하지 않는다.
- 이미 만들어져 있으면 완료 기준과 비교해 빠진 것만 채운다.

## ③ 검사 (이 순서대로, 각 칸은 반드시 그 직원에게 맡긴다)
1. 🧪 **date-tester** 에게: "PRD ○ 완료 기준으로 테스트를 확인·추가하고 돌려서 표로 보고해 줘"
2. 📋 **spec-checker** 에게: "PRD ○ 완료 기준과 하지 않을 것 기준으로 판정해 줘"
3. ⭐📝 **report-checker** 에게: "○ 기능의 경고·변경 문장이 보고에 그대로 쓸 수 있는지 검사해 줘"
- 검사 직원 셋은 서로 상관없는 일이라 **동시에** 맡겨도 된다.

## ④ 고치기 · 재검사
- ❌ 가 나오면 팀장(메인 Claude)이 고치고, **❌ 를 낸 그 직원에게 다시** 검사받는다.
- 같은 직원이 같은 ❌ 를 **3번** 내면 멈추고 대표에게 묻는다.
- ⭐ 대표 규칙: **date-tester 가 경계값(-1·0·7·8일) ❌ 를 내면 고치기 전에 무조건 멈추고 대표에게 보고한다.**

## ⑤ 출시
- 셋 다 통과하면 PRD.md 「출시 체크」의 해당 기능을 `[x]` 로 바꾸고 CHANGELOG.md 에 한 줄 추가.
- GitHub 에는 올리지 않는다. 커밋 메시지만 제안한다. (예: "F2 L/C 선적 기한 경고 출시")
